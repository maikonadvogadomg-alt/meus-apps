📚 Guia Completo: Código Único vs Modular

1️⃣ O QUE É CÓDIGO ÚNICO?

Definição

Código único é quando TUDO está em UM arquivo só.

HTML, CSS, JavaScript, tudo junto.

Exemplo de Código Único:

<!DOCTYPE html> <html> <head> <style> body { background: blue; } </style> </head> <body> <h1>Olá</h1> <script> console.log('Funciona!'); </script> </body> </html>

✅ Vantagens do Código Único:

  • Simples de abrir (só 1 arquivo)
  • Fácil de testar (tudo junto)
  • Não precisa de servidor
  • Funciona em qualquer lugar

❌ Desvantagens do Código Único:

  • Fica MUITO grande (difícil de ler)
  • Difícil de encontrar erros
  • Difícil de reutilizar partes
  • Confuso quando cresce

2️⃣ O QUE É CÓDIGO MODULAR?

Definição

Código modular é quando você SEPARA em vários arquivos.

Cada arquivo faz UMA coisa.

Exemplo de Estrutura Modular:

/meu-projeto/ ├── index.html (estrutura) ├── style.css (aparência) ├── app.js (funcionamento) └── utils.js (funções úteis)

✅ Vantagens do Código Modular:

  • Fácil de ler (cada arquivo é pequeno)
  • Fácil de encontrar erros
  • Fácil de reutilizar partes
  • Fácil de trabalhar em equipe
  • Fácil de atualizar

❌ Desvantagens do Código Modular:

  • Mais arquivos para gerenciar
  • Precisa de servidor para testar
  • Mais complexo no início

3️⃣ COMPARAÇÃO LADO A LADO

📦 CÓDIGO ÚNICO

Arquivo: index.html (1 arquivo)

Tamanho: Pode ficar gigante

Uso: Projetos pequenos

Exemplo: Seu editor anterior

🧩 CÓDIGO MODULAR

Arquivos: index.html, style.css, app.js, etc

Tamanho: Vários pequenos

Uso: Projetos grandes

Exemplo: Aplicações profissionais

4️⃣ OS 3 TIPOS DE CÓDIGO MODULAR

Tipo 1: Modular por Arquivo (Simples)

Você separa em 3 arquivos básicos:

index.html ← Estrutura (HTML) style.css ← Aparência (CSS) app.js ← Funcionamento (JavaScript)

Como funciona:

<!-- index.html --> <link rel="stylesheet" href="style.css"> <script src="app.js"></script>

Tipo 2: Modular por Funcionalidade (Médio)

Você separa por O QUE CADA COISA FAZ:

/editor/ ├── index.html ├── css/ │ ├── navbar.css │ ├── sidebar.css │ └── editor.css ├── js/ │ ├── files.js │ ├── preview.js │ └── editor.js

Cada arquivo faz UMA coisa:

  • files.js = gerencia arquivos
  • preview.js = gerencia preview
  • editor.js = gerencia editor

Tipo 3: Modular Completo (Avançado)

Você usa FRAMEWORKS como React, Vue, Angular:

/projeto/ ├── src/ │ ├── components/ │ │ ├── Editor.js │ │ ├── Preview.js │ │ └── Sidebar.js │ ├── utils/ │ │ └── files.js │ └── App.js ├── package.json └── build/

Nota: Isso é para projetos MUITO grandes. Você não precisa disso agora.

5️⃣ A DIFERENÇA ENTRE "COR" E "MOTOR"

🎨 COR = CSS (Aparência)

É tudo que você VÊ:

  • Cores (background, color)
  • Tamanhos (width, height)
  • Posições (position, flex)
  • Bordas (border, border-radius)
  • Sombras (box-shadow)

Pode remover CSS que nada quebra.

⚙️ MOTOR = JavaScript (Funcionamento)

É tudo que FUNCIONA:

  • Clicar em botão (onclick)
  • Abrir arquivo (openFile)
  • Salvar (saveFile)
  • Atualizar preview (refreshPreview)
  • Importar/Exportar ZIP

Se remover JavaScript, nada funciona.

Exemplo:

/* COR (CSS) - Só aparência */ button { background: blue; ← Cor border-radius: 5px; ← Formato padding: 10px; ← Tamanho } /* MOTOR (JavaScript) - Funciona */ button.onclick = function() { saveFile(); ← Faz algo }

6️⃣ COMO SEPARAR CORRETAMENTE

Passo 1: Identifique as Partes

Seu editor tem essas partes:

  • Navbar: Botões no topo
  • Sidebar: Árvore de arquivos
  • Editor: Textarea com código
  • Preview: Iframe com resultado

Passo 2: Crie Arquivos Separados

/editor/ ├── index.html (estrutura) ├── style.css (aparência) ├── app.js (lógica principal) ├── files.js (gerencia arquivos) ├── editor.js (gerencia editor) └── preview.js (gerencia preview)

Passo 3: Cada Arquivo Faz UMA Coisa

/* files.js - Só gerencia arquivos */ function openFile(path) { ... } function saveFile() { ... } function deleteFile(path) { ... } /* editor.js - Só gerencia editor */ function updateLineNumbers() { ... } function syncScroll() { ... } /* preview.js - Só gerencia preview */ function refreshPreview() { ... }

7️⃣ COMO CONECTAR OS ARQUIVOS

No index.html, você conecta assim:

<!DOCTYPE html> <html> <head> <!-- Conecta o CSS --> <link rel="stylesheet" href="style.css"> </head> <body> <!-- Conecta os JavaScripts --> <script src="files.js"></script> <script src="editor.js"></script> <script src="preview.js"></script> <script src="app.js"></script> </body> </html>

⚠️ IMPORTANTE:

A ordem importa! Se app.js usa funções de files.js, você deve carregar files.js ANTES de app.js.

8️⃣ EXEMPLO PRÁTICO: SEU EDITOR

Antes (Código Único - Gigante):

index.html (1500+ linhas) ├── HTML (estrutura) ├── CSS (cores, estilos) └── JavaScript (funcionamento)

Depois (Código Modular - Organizado):

/editor/ ├── index.html (100 linhas - só estrutura) ├── style.css (300 linhas - só aparência) ├── app.js (200 linhas - lógica principal) ├── files.js (150 linhas - gerencia arquivos) ├── editor.js (100 linhas - gerencia editor) └── preview.js (100 linhas - gerencia preview)

✅ Resultado:

  • Cada arquivo é pequeno (fácil de ler)
  • Fácil de encontrar o que precisa
  • Fácil de corrigir erros
  • Fácil de adicionar novas funcionalidades

9️⃣ QUANDO USAR CADA UM?

📦 USE CÓDIGO ÚNICO QUANDO:

  • Projeto é muito pequeno
  • Quer testar algo rápido
  • Não precisa de manutenção
  • Está aprendendo

🧩 USE CÓDIGO MODULAR QUANDO:

  • Projeto é grande
  • Precisa manter por tempo
  • Trabalha em equipe
  • Quer adicionar funcionalidades

🔟 RESUMO FINAL

O Que Você Aprendeu:

  • ✅ Código único = 1 arquivo (simples, mas fica gigante)
  • ✅ Código modular = vários arquivos (organizado, fácil de manter)
  • ✅ CSS = cor/aparência (pode remover)
  • ✅ JavaScript = motor/funcionamento (não pode remover)
  • ✅ Separar por funcionalidade (cada arquivo faz 1 coisa)
  • ✅ Conectar no index.html com <link> e <script>

🎯 Próximo Passo:

Agora que você entende a diferença, você pode:

  1. Pegar seu editor que funcionava
  2. Separar em arquivos (HTML, CSS, JS)
  3. Testar cada parte
  4. Adicionar novas funcionalidades sem quebrar
